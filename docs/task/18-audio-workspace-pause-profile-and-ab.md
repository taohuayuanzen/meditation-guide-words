# T18：音频工作区停顿档案、预计时长与模型 A/B 验收

> 任务状态：⏳ 待实施

## 任务目标

在音频工作区提供首期可用的“选择停顿档案 → 生成编排预览 → 查看预计总时长 → 确认生成”体验，并通过固定样本对 `qwen-audio-3.0-tts-plus` 与支持 SSML 的 CosyVoice 方案进行 A/B 验证。默认模型保持 Qwen，不因本任务自动切换。

完成后的用户流程：

```text
选择支持可控留白的新脚本
  → 填写声音描述
  → 选择轻柔 / 标准 / 深度
  → 生成编排预览
  → 查看语音、自然停顿、冥想留白和预计总时长
  → 确认生成音频
  → 查看分段进度、最终时长和预计偏差
```

---

## 前置依赖

- T16 完成：Script 能力标识、三档停顿档案和 render plan preview API 可用。
- T17 完成：AudioTask 快照、分段合成、静音拼接、进度和实测时长可用。
- 设置页可选择 `qwen-audio-3.0-tts-plus` 和 CosyVoice 模型及其合法音色。

| 决策项 | 结果 |

| 用户控制粒度 | 选择停顿档案并显示预计时长，不做逐段时间轴编辑 |
| 停顿档案 | 轻柔 / 标准 / 深度 |
| 默认模型 | `qwen-audio-3.0-tts-plus` |

| 旧脚本 | 首期不兼容，不提供自动推断 |
| 总时长 | 展示包含语音、自然停顿和冥想留白的完整时长 |

## 1. 工作区信息架构

调整 `AudioWorkspace.tsx`，按以下顺序组织：

1. 引导词选择
2. 引导词正文预览
3. 停顿档案
4. 声音描述
5. 编排预览
6. 确认生成
7. 任务列表

避免把所有设置堆在单个文本框旁。停顿档案和预计时长属于生成核心信息，应始终可见。

---

## 2. 脚本选择与旧脚本处理

脚本列表根据 `pause_capable` 展示状态：

- 新格式：正常选择，显示目标时长。
- 旧格式：显示“旧版引导词，不支持可控留白”，禁用新的音频生成入口。

规则：

- 不静默对旧脚本使用原来的整篇一次合成。
- 不调用 App B 猜测旧脚本停顿。
- 可提供“前往引导词工作区重新生成”的导航，不在本任务中实现自动转换。
- 历史脚本仍可在其他已有功能中查看、编辑和删除。
- 历史 AudioTask 仍可播放、下载和查看。

---

## 3. 停顿档案选择器

展示为三张单选卡或紧凑的 segmented control：

| 档案 | 用户文案 | 适用场景 |
|---|---|---|
| 轻柔 | 节奏连贯，留白较短 | 简短放松、初次体验 |
| 标准 | 呼吸与观察留白均衡 | 日常正念练习 |
| 深度 | 节奏更慢，练习留白更充分 | 深度身体扫描、睡前练习 |

要求：

- 默认选择“标准”。
- 实际 ID 使用 `gentle_v1/standard_v1/deep_v1`，前端不保存毫秒映射。
- 档案定义从后端只读 API 获取。
- 切换脚本或档案后，已有 preview 标记为过期，必须重新生成。
- 切换语言只改变显示文案，不改变档案 ID。

## 4. 两步式生成流程

### 第一步：生成编排预览

按钮文案：`生成预览`。

启用条件：

- 已选择 `pause_capable=true` 的脚本。
- 已选择停顿档案。
- 声音描述非空。
- 当前没有正在请求的 preview。

调用 T16 的 preview API。此步骤可能调用 Dify App B，但不得调用 TTS 或创建 AudioTask。

### 第二步：确认生成音频

preview 成功后展示摘要，再提供 `确认生成音频`：

```text
预计总时长        9分52秒
目标时长          10分00秒
预计语音          6分52秒
自然微停顿        34秒
冥想留白          2分26秒
确定性留白数量    12处
最长单次留白      20秒
模型              qwen-audio-3.0-tts-plus
音色              龙安灵心
停顿档案          标准
```

确认时提交 preview 返回的规范化 plan 和 digest。任务创建成功后：

- 清除当前 preview，避免重复提交同一计划。
- 保留用户选择的脚本、档案和声音描述，方便继续生成不同版本。
- 显示任务创建成功提示并刷新任务列表。

### 4.1 预览失效

以下变化使 preview 失效：

- 脚本变化
- 停顿档案变化
- 声音描述变化
- 当前 TTS provider/model/voice 配置变化
- Script 在其他页面被修改

后端返回冲突时，前端明确提示重新生成预览，不自动使用旧 plan。

## 5. 预计时长展示

展示原则：

- 主数字使用完整预计总时长。
- 清楚说明“预计总时长包含朗读、自然停顿和冥想留白”。
- 同时展示目标时长和预计偏差。
- 偏差在 `±10%` 内使用中性提示；超出时提示用户可调整档案或返回修改引导词。
- 不承诺最终时长精确等于预计值。
- 任务完成后显示实测时长和预计偏差，用于人工判断估算质量。

格式化要求：

- 小于 1 分钟显示秒。
- 大于等于 1 分钟显示“X分Y秒”。
- 英文环境使用 `Xm Ys`。
- 不直接暴露毫秒或内部 estimation version，诊断详情除外。

## 6. 任务卡与进度

扩展 `TaskItem`：

- 显示阶段：排队、分段合成、拼接、编码、校验、完成、失败。
- 分段合成阶段显示 `已完成 N / M 段`。
- 显示快照：provider、model、voice、停顿档案。
- 显示预计总时长；完成后显示实测总时长和偏差。
- 失败时说明重试会复用相同 render plan 和 TTS 快照。
- 本地拼接/编码失败的重试提示“不会重新生成已完成语音段”。
- 当前全局模型与任务快照不一致时，任务卡仍显示任务自己的模型，不使用设置页当前值覆盖。

列表接口不返回完整 render plan，任务卡不展示逐段文本，避免泄露和无必要的数据传输。

---

## 7. 错误与空状态

至少覆盖：

- 没有引导词：提示先在工作区 1 创建新格式引导词。
- 只有旧脚本：说明旧脚本不支持可控留白，并提供导航。
- preview JSON/校验失败：提示“音频编排失败”，保留输入供用户重试。
- 模型/音色不匹配：引导到 TTS 设置页。
- FFmpeg/FFprobe 不可用：禁用确认生成并引导到设置/运维说明。
- preview 过期：要求重新生成，不自动提交。
- segment 数过多：提示返回工作区 1 合并过细段落。
- 预计时长明显偏离目标：允许继续确认，但给出清晰警告。
- Worker 失败：显示可诊断的安全错误，不展示供应商凭证或服务器路径。

## 8. Qwen 与 CosyVoice A/B 方案

### 8.1 目的

验证两个问题：

1. 默认 Qwen + 后端静音是否已满足可控留白和自然度要求。
2. CosyVoice + SSML 对 10 秒以内停顿和句间自然度是否有显著收益，足以支持后续默认模型决策。

本任务只形成证据，不自动修改默认模型。

### 8.2 固定样本

至少准备 3 条新格式脚本：

| 样本 | 目标时长 | 重点 |
|---|---:|---|
| 呼吸安住 | 5 分钟 | 1～3 次呼吸留白、自然句间停顿 |
| 身体扫描 | 10 分钟 | 多个 10～30 秒练习留白 |
| 睡前放松 | 15 分钟 | 慢语速、长段落、结束整合留白 |

每条脚本分别使用轻柔、标准、深度中的至少两档；同一轮对比固定正文、档案、目标时长和尽可能接近的声音风格。

### 8.3 对比组合

```text
A：qwen-audio-3.0-tts-plus + 合法 Qwen 音色 + 后端静音
B：支持 SSML 的 CosyVoice 模型 + 明确支持 SSML 的合法音色
   + 10 秒内 SSML break + 超过 10 秒后端静音
```

模型和音色必须按阿里云官方列表匹配。不能将 Qwen 音色直接用于 CosyVoice。

### 8.4 评价指标

量化指标：

- 最终时长与目标时长偏差
- 确定性静音时长误差
- 失败率和重试次数
- TTS 请求数
- 生成耗时
- 实际费用（以阿里云账单为准）

人工盲听指标，1～5 分：

- 句间自然度
- 停顿位置合理性
- 留白时长舒适度
- 段落衔接是否突兀
- 音色稳定性
- 是否存在播音腔、赶读、爆音或拼接感
- 整体冥想可用性

### 8.5 默认模型变更门槛

本任务不预设 CosyVoice 胜出。后续如需切换默认模型，必须单独确认并创建新任务，至少依据：

- CosyVoice 在核心自然度指标上有稳定、可重复的明显提升。
- 合法音色、SSML、instruction 和 HTTP 接口均稳定。
- 成本、失败率、生成耗时和工程复杂度可接受。
- Qwen 现有任务和设置迁移方案明确。

## 风险备注

- preview 增加一步交互，但能避免用户在不知道总时长和留白结构时直接产生付费 TTS 任务。
- App B 预览本身可能调用 LLM，应避免输入变化时自动频繁请求；首期使用显式按钮。
- 不兼容旧脚本属于有意的首期范围限制，必须通过状态和引导减少困惑。
- 不同模型使用不同音色，A/B 无法做到完全相同发音人，评分应重点比较停顿和整体可用性，而非只比较音色偏好。
- 人工试听具有主观性，应隐藏模型标签、随机播放顺序并保存原始评分。
